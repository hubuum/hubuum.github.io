# Build Hubuum with us

Hubuum is developed in the open and licensed under MIT. Documentation fixes,
reproducible bug reports, integration experience, and code contributions help
make it useful across different environments.

## Find the right repository

- [Server](https://github.com/hubuum/hubuum): data model, API, permissions, and operations.
- [Frontend](https://github.com/hubuum/hubuum-frontend): browser workflows and frontend deployment.
- [CLI](https://github.com/hubuum/hubuum-cli): terminal commands, scripts, and extensions.
- [Rust client](https://github.com/hubuum/hubuum-client-rust): Rust APIs and client behavior.
- [Python client](https://github.com/hubuum/hubuum-client-python): Python APIs and client behavior.
- [Ecosystem website](https://github.com/hubuum/hubuum.github.io): this landing page and its content.
- [Shared documentation tooling](https://github.com/hubuum/.github): theme, site checks, and publishing workflows.

Use the affected project's issue tracker for questions and bugs. Include the
project version, server version where relevant, what you expected, and a small
reproduction. Remove tokens, passwords, and private inventory data from examples.

## Propose a change

Read the project's contributor instructions and compatibility policy first.
Keep documentation with the component that owns the behavior; link to shared
server concepts instead of maintaining copies in each client guide.

For a documentation correction, select the development edition and use its edit
link. Released documentation remains an immutable record of its source snapshot.

Report security vulnerabilities through the affected repository's private
security-reporting channel and published security policy.
